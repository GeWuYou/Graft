# 容器化应用运维平台实施路线

## 产品目标

Graft 首先服务个人与小团队的单机 Docker/Compose 运维，随后覆盖容器化建站。
当前已具备应用工作区、Docker 资源、Task、构建、平台备份、自更新及权限审计实现，
交付成熟度按完整用户操作与恢复证据判断。

## 首轮交付

1. 工程治理。统一产品定位、验证阶段和依赖入口，引入 Bun workspace 与 Turbo，
   合并 Go 测试和报告流，定向本地检查与完整 CI 各自提供证据。
2. 本机执行。Task Runtime 调度共享 Docker/Compose 适配，支持应用导入、部署、资源操作、日志与终端。
3. 构建与平台更新。构建材料与凭据绑定当前 attempt，平台更新由短生命周期 Controller 跨重启完成。
4. 迁移与诊断。明确 local/agent 模式切换条件，保留历史记录，执行失败具有稳定诊断与恢复入口。

架构依据为 [ADR-029](../design/decisions/ADR-029-local-application-operations.md)。
本轮实现与复验证据见 [治理归档](../public/archive/containerized-platform-governance/README.md)。

## 验收依据

- 全新数据目录安装后完成真实应用导入、部署、启停和资源操作，并核对 Docker 引擎状态。
- 构建推送、取消与凭据脱敏通过，更新具备备份、迁移、替换、健康与最终回执证据。
- 并发冲突、执行中断和不确定副作用具有持久化约束与人工核对路径。
- 既有安装经过显式预检切换，历史任务、审计和更新记录可读取。
- 前端缓存命中与源码、契约、配置、环境、锁文件、工具链失效均有证据，记录可比耗时。
- 定向检查与完整 CI 成功分别记录，运行验收覆盖其实际场景。

## 后续能力顺序

1. 可靠部署与更新。增加变更预览、健康核验、失败处置与明确恢复边界。
2. 应用数据备份恢复。覆盖应用配置、数据库导出与持久卷，验证隔离恢复。
3. 容器化建站。贯通端口、域名、反向代理、HTTPS 与证书续期。
4. 日常诊断。增强磁盘、端口、DNS、镜像仓库连通性、挂载权限和资源压力反馈。

远程多主机与宿主机原生软件管理各自依据实际需求独立立项。
