# 消除性操作契约收敛实施计划

## 1. 目标

本路线统一资源软删除、关系解除、凭据撤销、不可逆硬删除和外部资源销毁的调用者语义。统一对象是契约、重试、结果、权限、审计与恢复，不是把各模块业务规则塞进一个通用删除服务。

## 2. 分批顺序

### Batch 1：契约基础（已完成）

- 在既有 API 边界规范中固定 DELETE tombstone、硬删除命令、外部 Task 和批量事务语义。
- 增加 `x-graft-destructive` schema、统一批量结果 schema 和已有 OpenAPI 校验入口内的语义校验。
- 只校验真实声明；存量接口未迁移前不得用目标 metadata 掩盖运行时差异。

### Batch 2：软删除试点（已完成）

- 将用户软删除迁移为 `DELETE /api/users/{id}`。
- 验证第一次 204、同授权作用域第二次 204、详情 GET 404、列表隐藏。
- 删除 `/api/users/{id}/delete`，不保留 alias。

### Batch 3：关系与安全批量

- 关系解除统一使用 DELETE；普通批量允许 partial commit。
- role、permission、access binding 等安全敏感批量在一个事务内完成预校验和写入，失败时零提交。
- 成功响应统一使用 destructive batch result。

### Batch 4：不可逆数据库销毁

- 审计日志、应用日志等高风险硬删除迁移到 `POST .../deletions`。
- 强制 `Idempotency-Key`，持久化 operation receipt；重复 key 返回原 receipt/result，内容冲突返回 409。
- 批量请求限制数量并拒绝重复 ID。

### Batch 5：外部资源销毁

- Docker/Compose/云资源 remove、destroy、untag 等继续使用 POST action，但统一返回 202 Task receipt。
- HTTP 不等待外部 daemon；Task 提供 accepted/running/succeeded/failed/unknown/needs_attention 可恢复状态。
- 重试绑定稳定 operation identity，不根据一次网络超时推断成功或失败。

### Batch 6：全量收敛

- 为全部已迁移操作补齐 metadata，启用全量 coverage 阻断。
- 删除旧路径、旧 action response、模块私有 batch result 和不再使用的适配代码。
- 生成 server/web 派生产物并通过 cross-boundary 完整验证。

## 3. 统一批量结果

同步成功批量响应的 `data` 统一为：

```json
{
  "operation_id": "op_01J...",
  "summary": {
    "requested": 100,
    "succeeded": 98,
    "failed": 2
  },
  "results": [
    {"id": "123", "status": "deleted"},
    {"id": "456", "status": "failed", "code": "FORBIDDEN"}
  ]
}
```

`results` 保持请求顺序且每个请求 ID 恰有一项。partial 模式把逐项失败留在 200 结果中；atomic 模式预校验失败返回统一 4xx error envelope 且不提交任何项。

## 4. 完成条件

- canonical OpenAPI、server handler/service/store、生成 TypeScript 和真实 consumer 同步收敛。
- 高风险操作的授权、审计、确认、MCP 暴露和重试策略可由 metadata 自动检查。
- 外部副作用均有 Task receipt 和超时后恢复路径。
- 不存在旧路由 alias、重复 DTO、第二任务状态机或通用删除业务层。
