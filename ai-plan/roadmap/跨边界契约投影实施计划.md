# 跨边界契约投影实施计划

本计划实施《跨边界契约投影设计》，以现有 OpenAPI/codegen 与 Go contract 为输入，不引入 protobuf、共享运行时 package 或第二份 IDL。

## Phase 1：生成链与治理基线

- 明确并实现唯一顺序：OpenAPI bundle、Go bindings/runtime bundle、web OpenAPI schema、cross-boundary projection、drift check。
- 为 Go contract export descriptor 定义最小 metadata 与 `visibility=web` 边界；更新相应 contract governance 文档。
- 为 web generated contract 输出建立可重建位置；保持现有 OpenAPI schema consumer 不变。
- 将 OpenAPI freshness、projection freshness 和 visibility/duplicate checks 接入既有本地与 PR CI entrypoint，不建立第二套 CI 真值。

验收：临时生成与 tracked artifacts 一致；PR 可阻断生成漂移；API envelope 仍允许未知 `code`/`messageKey` 并提供 fallback。

## Phase 2：最小端到端试点

- 试点 platform error code、message key、header/auth scheme，以及一个模块的 permission、Docker error 或 realtime topic。
- web 改为直接导入 generated contract，删除相同语义的手工镜像；保留 web 私有 route/component/storage contract。
- 增加 descriptor completeness、generated output、unknown error/message fallback 和 runtime-authority boundary 的 focused tests。

验收：试点值从既有 Go/OpenAPI authority 生成，web 没有第二份字符串；生成值不改变 server 运行时 permission/menu/capability 判定。

## Phase 3：扩展、收敛与遗留清理

- 迁移全部 web-visible permission、API path、公开业务 enum、notification navigation、realtime topic、公开 config/feature key 与 capability key。
- 将 HTTP enum/path 的 owner 收敛到 OpenAPI；将非 HTTP value 的 owner 收敛到 Go contract/descriptor；禁止重复投影。
- 清除同语义的手写 web contract；仅保留有 expiry 的 generated re-export 过渡，并在 cleanup batch 删除。
- 让 drift gate 报告 deprecated、orphan 与 duplicate semantic value，作为正常 CI evidence。

验收：新增 cross-boundary value 的 owner 和消费路径可由设计、descriptor 与 generated output 追溯；API 兼容策略与现有 OpenAPI deprecation/lifecycle 一致。
