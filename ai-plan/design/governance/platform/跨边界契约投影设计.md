# 跨边界契约投影设计

## 1. 目标与范围

本设计在既有《契约治理与魔法值治理规范》基础上，定义 `server -> web` 的 Cross-boundary Contract Projection。它消除 `web` 对 server 稳定值的手工镜像，覆盖 error code、message key、permission、业务 enum、realtime topic、公开配置/feature key 与 capability key，而不是只解决某一种字符串。

本设计不引入 protobuf、共享运行时 package、第二份 IDL 或新的业务 authority；它只把已有 authority 投影为受控的 TypeScript 派生产物。

## 2. Authority 模型

同一契约按语义保留唯一 canonical authority：

| 契约类别 | Canonical authority | web 消费方式 |
| --- | --- | --- |
| HTTP path、operation、request/response、public wire enum、HTTP/realtime ticket schema | `openapi/**` | 既有 OpenAPI generated schema 与 path projection |
| platform error code、message key、header/auth scheme | `server/internal/contract/**` | Go contract projection |
| module permission、message、业务 enum、module-local topic、公开 capability | `server/modules/<name>/contract/**`、module descriptor 或 `server/internal/moduleapi/**` | Go contract projection |
| 菜单、权限与 capability 的当前有效集合 | server bootstrap / runtime response | runtime response；generated value 只供静态引用 |
| web 私有 route name、component、storage/query key、展示实现 | `web/**` | web local contract；不得伪装为 server contract |

OpenAPI 继续是 HTTP wire authority。Go server contracts 继续是所有非 HTTP 稳定值的 authority。generated TypeScript、OpenAPI bundle 和 generated Go bindings 均为 derived artifact，不能反向成为 authority。

## 3. 投影模型

### 3.1 Export descriptor

每个需要在 `web` 使用的非 HTTP Go contract，由其 canonical owner 提供显式 export descriptor。descriptor 至少包含 `id`、`kind`、`owner`、`lifecycle`、`visibility` 与可选 `replacement`；其 value 必须直接引用既有 typed Go constant，禁止再次书写同一字符串。

`visibility=web` 是唯一可生成到 web bundle 的入口。`server`、`internal`、敏感配置、授权策略细节和未公开 capability 不能仅因有常量就被投影。descriptor 是 discoverability 与生成索引，不是集中定义全部值的大字典。

生成器按 owner 和 kind 输出 `web/src/contracts/generated/**` 的 TypeScript literal object、literal union 和必要的 type guard。模块私有契约生成到模块对应的 generated 子路径；平台公共值生成到平台 generated 子路径。手写 web contract 不得与 generated 值并行定义或 re-export 为长期真值。

### 3.2 OpenAPI 投影

OpenAPI 既有 `openapi-typescript` 生成类型链保持不变。投影器从 canonical bundle 按 `operationId` 生成运行时 API path map；HTTP schema 已公开的 enum 只从 OpenAPI 投影，不能再由 Go descriptor 重复导出。

OpenAPI extension 仅在 HTTP contract 需要提供 projection metadata 时使用，且只服务于 wire contract 的 owner/lifecycle/visibility 信息。它不承载 module permission、server-only config、动态 capability 或 module lifecycle，不把 OpenAPI 膨胀成非 HTTP 注册中心。

### 3.3 运行时与兼容

API error envelope 的 `code`、`messageKey` 保持开放 `string`，已生成 union 只用于 web 静态引用和 type guard。web 必须对未知 code/key 使用 server supplied fallback，不得因 server 先发布了新值而拒绝响应或产生类型断言失败。

menu、permission 和 capability 的实际可用性仍以 server bootstrap/runtime response 为准；generated contracts 不授予权限，也不替代运行时过滤。compatibility 仍遵守既有 lifecycle：新增是向后兼容的；rename/remove/deprecate 先修 canonical authority，再在必要时建立有 expiry 的桥接。

## 4. 生成与 Drift Gate

唯一生成顺序固定为：

1. bundle canonical OpenAPI fragments；
2. 生成 Go OpenAPI bindings 与 runtime embedded bundle；
3. 生成 web OpenAPI schema；
4. 从 canonical OpenAPI 和 Go export descriptors 生成 web cross-boundary contracts；
5. 运行 freshness / duplicate / visibility / lifecycle checks。

生成命令必须先写临时目录再比较 tracked output；CI 不接受未提交的派生产物。检查至少阻断：OpenAPI 或 projection output 漂移、web-visible descriptor 缺 metadata、同一 semantic value 的重复 authority、server-only value 输出到 web、deprecated value 的新引用，以及 OpenAPI enum 与 Go projection 的重复 owner。

PR CI 和本地 completion entrypoint 都复用同一 drift gate；它们不能各自维护另一套扫描规则。OpenAPI 的现有 generation/check 链不被替换，projection check 作为其后续阶段接入。

## 5. 不采用的方案

| 方案 | 结论 |
| --- | --- |
| Shared Package | Go/TS 需要新共享格式或双语运行时 package，容易形成第二 authority；不采用。 |
| 仅 Go 自动生成 TS | 是核心能力，但不能代替 OpenAPI 对 wire schema/path/公开 enum 的 authority；作为混合方案的一半采用。 |
| 仅 OpenAPI Extension | 适合 HTTP metadata，不能承载 module descriptor、permission registry 或非 HTTP runtime 语义；仅补充采用。 |
| 独立 Contract Generator + 新 IDL | 会引入并行定义和迁移成本；不采用。 |
| Authority-aware Contract Projection | 读取既有 Go/OpenAPI authority，输出 TypeScript derived artifacts；采用。 |

## 6. 验收标准

- server 新增一个 `visibility=web` 的既有 contract 后，单次 generate 可得到 TypeScript 可引用值。
- web 不再手写相同 semantic value；未知 error/message 值仍有用户可见 fallback。
- 新增 API path 或 public wire enum 只更新 OpenAPI source；非 HTTP stable value 只更新 Go owner；生成输出同步提交。
- CI 能以临时生成比较发现 output 漂移，且不会把生成物、registry 或 web mirror 误认作 canonical authority。
