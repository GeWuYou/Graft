# 项目分页列表规范设计

本文档是 `web` 分页与列表管理页的长期设计真值。它定义页面 surface、信息层级、响应式呈现、动作层级、状态反馈和共享组件边界；业务页面必须复用既有共享能力，不得以页面私有样式或第二套组件结构绕开这些约束。

适用范围：

- `web/src/modules/**` 下的分页列表页和资源管理页。
- `web/src/shared/components/management/**`、`web/src/shared/components/responsive/**` 及其消费页面。
- `list-form-detail`、`query-builder-list-detail`、`log-audit` 页面类型中的列表结果面。

非目标：改变业务 API、权限语义、数据语义，或将所有列表页面强制为同一种筛选表单。

## 1. 页面 Surface 与响应式 Authority

- 分页 / 表格列表路由声明 `pageKind: 'list'`；`web/src/utils/route/meta.ts` 将其解析为 `paged-table` surface。
- `meta.pageSurface` 是显式覆盖入口，只在页面语义确有差异时使用。业务页面不得通过局部 `max-width`、负 margin 或额外容器修正壳层宽度。
- `paged-table` 使用全可用宽度；详情、调查和表单阅读页使用 `form-detail` 有界宽度；Dashboard 保持自身有界 surface。
- 宽表列表由壳层根据 route metadata 使用 `wide-table` 侧边栏动效。业务页面不得添加局部侧边栏样式或按 path 维护动画白名单。
- `ResponsiveTable` 是表格与卡片展示的唯一响应式 renderer。页面只声明列优先级与卡片槽位，不得用 CSS 或 `v-if` 维护第二份卡片布局。
- `data` 表格在 compact density 可转换为记录摘要；短实体管理列表可声明 `entity` 卡片。compact `entity` 卡片的选择状态由卡片复选框表达，隐藏表格不得继续接收 `selected-row-keys`，避免出现全宽蓝色选择条。

## 2. 官方分页列表结构

```text
<ListPage>
  <PageHeader />
  <PageStatistics />   <!-- optional -->
  <PageFilters />      <!-- optional -->
  <PageToolbar />
  <PageContent />
  <PagePagination />   <!-- paginated pages only -->
</ListPage>
```

| 区域 | 必选性 | 规则 |
| --- | --- | --- |
| `PageHeader` | 必须 | 只承载标题、简短说明与页面定位，不放刷新、列设置或状态 Badge 墙。 |
| `PageStatistics` | 可选 | 仅表达服务端资源集合聚合，不用 Card、Badge、Chip 或 Pill 组成统计区。 |
| `PageFilters` | 有查询条件时必须 | 承载查询条件、查询与重置，不与 Toolbar 混排。 |
| `PageToolbar` | 必须 | 承载列表视图工具与选中后的批量操作。 |
| `PageContent` | 必须 | 使用统一表格、实体卡片或业务结果面，并统一处理状态反馈。 |
| `PagePagination` | 分页页必须 | 使用共享分页壳，不在页面重建第二套分页布局。 |

默认页面外层内边距为 24px，区域之间为 16px。可选区域缺失时不占位；结果面、表格卡片和筛选面默认使用 24px 水平内边距，禁止重复 Card 嵌套。

## 3. Toolbar、批量操作与行操作

Toolbar 固定左右布局：左侧是选中后出现的批量操作；右侧顺序为刷新、列设置、密度、导入导出、更多。刷新、列设置与密度是当前列表视图操作，必须相邻置于右侧；Header 和 FilterBar 不得放入这些工具。

批量操作必须使用 `ManagementBatchBar`：

- 宽屏可直接展示业务动作与取消选择。
- 窄屏必须保留选中数量和取消选择在同一水平行；业务动作收敛到一个带文本的“批量操作”下拉入口。
- 页面只提供下拉动作数据及处理事件，不得自行实现窄屏收纳布局，也不得把业务动作垂直堆叠成按钮列。

每行默认仅显示一个主操作和一个“更多”入口：主操作默认是“详情”；没有详情页时才可替换为唯一主要动作。编辑、删除、日志、复制、启动、停止、重启等进入更多菜单；危险动作必须二次确认，并使用 TDesign `error` 语义色。禁止并列多个主操作。

卡片行操作同样使用 `TableActionMenu`：操作区固定在卡片右下角，详情为 `primary + outline`，更多为 `default + outline`；没有次级操作时隐藏更多，不能用省略号图标替代有文本的更多按钮。

## 4. Entity 卡片选择与信息密度

带批量选择的实体卡片遵循固定结构：

```text
左上：复选框
第二行：身份 / 标题 / 副标题 / 状态与保护标记
主体：资源关键信息
右下：详情 + 更多
```

- 复选框必须独占左上行，不得与身份信息争抢同一行，也不得挤入右下操作区。
- 身份与标题内容必须从复选框后的下一行开始；复选框本身高度较小，不构成压缩主体信息的理由。
- 状态和保护标记位于标题区域。保护标记使用短文案，并通过 `title` 保留完整语义，避免占用主体信息和操作按钮宽度。
- 选择反馈以复选框、选择摘要和明确的卡片边框状态为准；不得使用横跨卡片的蓝色选中条。
- 用户、角色、权限、容器及所有 `entity` 卡片均遵循该结构，页面不得定义私有例外。

## 5. 筛选与搜索

筛选条件只放在 FilterBar。轻筛选页的搜索框桌面宽度为 240px 到 320px，推荐 `width: clamp(240px, 28vw, 320px)`；重筛选页为 360px 到 480px，推荐 `width: clamp(360px, 36vw, 480px)`。小屏可独占一行，但不应被右侧按钮压缩到低于最小宽度。

搜索控件与筛选控件使用统一 spacing token；长 placeholder 应移入 tooltip 或高级筛选说明。共享筛选组件只负责布局、间距与槽位，不拥有业务查询、API 调用或 route query 同步。

## 6. 数据、列与分页

Statistics Bar 只展示服务端聚合数据，格式为行内文本，例如“总数 19 | 运行中 18 | 停止 1”。`total` 表示当前筛选条件下的资源集合总数；当前页条数须明确标记为“当前页 N 条”。Desktop 保持单行，Mobile 横向滚动，不拆为统计卡片。

表格主列靠左；状态使用 TDesign `Tag`；时间使用统一格式；`ID`、`request_id`、`event_type`、`resource` 等长文本应截断并通过 tooltip 提供完整值。操作列固定右侧，标题统一为“操作”，超过两个动作时使用“更多”。

分页区域左侧展示范围与总数，右侧使用 TDesign Pagination。分页默认 page size 为 20，轻量管理页可用 10；可选值统一为 `10 / 20 / 50 / 100`。首次进入和重置筛选均查询第一页。API 已采用 `limit` / `offset` 时，UI 映射为 `limit = pageSize`、`offset = (current - 1) * pageSize`，不得伪造 `page` / `page_size` 契约。

## 7. 状态反馈

| 状态 | 展示规则 | 恢复动作 |
| --- | --- | --- |
| 首次加载 | 固定高度 Skeleton，避免数据返回后布局跳动。 | 无需额外操作。 |
| 刷新中 | 保留已有数据，仅在刷新控件和结果面显示局部 loading。 | 可等待或再次刷新。 |
| 无数据 | 明确该资源当前为空。 | 有创建权限时可提供创建入口。 |
| 筛选无结果 | 明确没有符合当前筛选条件的数据。 | 提供重置筛选。 |
| 加载失败 | 明确失败原因，不伪装为空状态。 | 提供重试。 |

只读页面的筛选无结果只提供恢复筛选动作。错误态、空态、刷新态和首次加载态必须可区分。

## 8. 共享组件边界

- `ManagementPagedTable` 负责统一分页表格、列集、实体卡片呈现与紧凑模式选择态隔离。
- `ManagementBatchBar` 负责选中摘要、取消选择和窄屏批量动作下拉的布局约束。
- `TableActionMenu` 负责详情与更多的行 / 卡片动作层级。
- `ManagementTablePagination` 负责默认 page size、可选值与分页 footer。
- `ResponsiveTable` 负责表格与卡片 renderer 的响应式切换。

业务页面拥有筛选字段、列定义、业务动作、API 查询和 route query 语义。共享组件不得接管业务状态，也不得新建第二套 Table、Pagination 或响应式卡片运行基线。新增或修改这些共享资产前，必须按 `.ai/registries/web-shared-assets.yaml` 与共享资产复用治理规范完成复用检查和登记评估。

## 9. 验收与反模式

验收至少覆盖宽屏、窄屏、暗色主题、英文文案、列设置、分页、route query 恢复和详情入口。页面必须保持业务 API、权限与数据语义不变。

以下情况不符合本规范：

- Header 放统计、刷新、列设置或运行状态 Badge 墙。
- Toolbar 放搜索、状态筛选、日期筛选、查询或重置。
- FilterBar 与 Toolbar 混排，或同一页面存在两个刷新按钮。
- 窄屏批量操作纵向堆叠，或绕开 `ManagementBatchBar` 手写下拉布局。
- 实体卡片把复选框与身份信息塞在同一行、把操作放到非右下位置，或使用全宽蓝色选择条。
- 卡片 / 行并列多个主操作，或以无文字省略号替代“更多”。
- Statistics 使用 Badge 墙、Chip、Pill 或 Dashboard Card 网格，或把当前页数量标为资源总数。
- 页面通过负 margin、局部宽度或嵌套 Card 修正标准层级。
- 空状态只显示“暂无数据”，没有适合当前权限和状态的恢复动作。
