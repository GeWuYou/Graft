# Graft 导航与资源路由信息架构规范

## 1. 目的与权威边界

Graft 是自托管应用平台，不以 Docker、Compose、Kubernetes 或其他 Runtime 技术组织用户可见导航。本规范是 Web 导航、UI route、全局入口和对象详情能力的仓库级设计权威；模块 descriptor、菜单 bootstrap 和 web 路由装配必须以它为分类依据。

导航用于帮助用户发现领域能力，UI URL 用于标识稳定资源。二者独立：改变菜单层级不得要求改变资源 URL，新增 Runtime 不得要求重构导航或 URL。

本规范只约束用户可见 UI URL；HTTP API endpoint 的路径由服务端 API 边界治理单独决定，不在本次迁移范围内。

## 2. 导航分类法

一级导航只表示以下领域。分组无授权可见子项时不得渲染，因此 Build 与 Resources 虽为正式领域，当前可以隐藏。

| 领域 | 管理对象 | 示例 |
| --- | --- | --- |
| Application | 用户交付、部署或运行的业务资产 | Projects、Templates、Releases、Catalog |
| Infrastructure | 应用运行所在的平台与环境 | Hosts、Containers、Clusters、Networks、Storage |
| Build | 应用生成过程 | Build Jobs、Image Builds、Artifacts、Cache |
| Resources | 可被多个对象引用、但自身不运行的共享依赖 | Credentials、Registries、Secrets、Config、Template Repositories |
| Observability | 运行数据和统一分析 | Logs、Metrics、Alerts、Traces、Events、Platform diagnostics |
| Security | 平台身份、授权和安全留痕 | Users、Roles、Permissions、Tokens、Audit |
| Platform | Graft 自身的管理能力 | Settings、Automation、Announcements、Plugins、License |

二级菜单必须是用户会主动寻找的业务对象或平台能力。技术实现不得成为菜单领域或菜单名称，包括 Docker、Compose、Podman、containerd、Kubernetes、Nomad、OCI、Helm、Git、SSH、Workspace、Authority 与 Snapshot。

## 3. Runtime、Source 与对象能力

- Runtime 是对象属性而非导航：Project 可以选择 Compose、Kubernetes 或未来 Runtime，但仍属于 Application。
- Source 是创建管道而非对象类别：Blank、Template、Git Repository、Import Existing、ZIP、OCI 与 Remote Host 都是 `Project Source`，不得产生 `Git Project` 或 `Compose Project` 这类菜单。
- Template 是具有独立创建、编辑、版本、发布生命周期的可交付资产时才进入 Application。当前 Template 仅为 Project 创建来源，不新增可见菜单；Template Repository 属于 Resources。
- Terminal、Files、Logs、Exec、Shell 与 Console 都是对象能力，必须依附 Host、Project 或 Container detail，不能成为一级菜单。
- Notification Center 是菜单外的全局入口，不能从 Platform 或 Observability 菜单派生。

## 4. UI 路由规则

UI URL 必须表达稳定资源模型，并且独立于菜单层级。禁止把导航领域名、Runtime 技术或创建来源编码进 UI URL。例如 Project 使用 `/projects/**`，不使用 `/application/projects/**`、`/compose/projects/**` 或 `/git-projects/**`。

迁移 UI route 时不得保留旧路径 alias、redirect 或兼容菜单节点。若必须例外，必须先按根 `AGENTS.md` 的 compatibility 例外规则记录 authority、原因、消费者、清理触发条件和验证范围。

## 5. 当前映射

| 当前能力 | 导航归属 | Canonical UI URL | 说明 |
| --- | --- | --- | --- |
| Projects 与创建来源 | Application > Projects | `/projects/**` | Template 当前仅为 Source |
| Containers 与详情能力 | Infrastructure > Containers | `/containers/**` | Terminal/Files 等留在 detail |
| Graft Platform Instance diagnostics | Observability > System | `/system/overview`, `/system/runtime`, `/system/dependencies`, `/system/modules` | 不是 Host 或 OS 管理 |
| Access-control overview | Security > Access control | `/access-control/overview` | 概览是 Security 能力 |
| Users | Security > Users | `/users` | 资源 URL 不带导航组 |
| Roles | Security > Roles | `/roles` | 资源 URL 不带导航组 |
| Permissions | Security > Permissions | `/permissions` | 资源 URL 不带导航组 |
| Audit overview and logs | Security > Audit | `/audit/overview`, `/audit/logs` | Audit 为安全留痕 |
| Access and application logs | Observability > Logs | `/logs/access`, `/logs/application` | 统一分析入口 |
| Scheduled tasks | Platform > Automation | `/scheduled-tasks` | 平台自动化能力 |
| System configuration | Platform > System configuration | `/system-config` | 平台自身配置 |
| Announcements | Platform > Notifications | `/announcements` | 平台通知管理 |
| Notification Center | Global entry | `/notifications` | 不进入可见菜单树 |

## 6. 新功能决策门

新增或移动功能前必须回答：用户真正管理的对象是什么；它是否共享资源；它是否只是技术实现；它是否只是对象能力；以及新增 Runtime 是否会迫使导航重构。无法确定对象、领域、父节点或稳定资源边界时，必须在注册菜单、UI route、alias、redirect 或占位页之前停止，并请求产品决策。`graft-navigation-route-governance` 是该门的执行技能。
